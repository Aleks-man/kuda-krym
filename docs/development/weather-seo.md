# SEO страниц погоды

Страницы городов и побережья имеют отдельные canonical URL, метаданные с названием
места и периодом прогноза. Каталог /coast содержит обычные ссылки на все города;
поисковику не требуется пользоваться поиском или картой.

Основной почасовой прогноз рендерится на сервере без потоковой Suspense-границы:
он виден в HTML без выполнения скрипта раскрытия. Страница ожидает загрузку
прогноза перед отправкой основного содержимого. Загрузочные экраны каталогов
изолированы в группах (catalog); публичные URL не изменились. Дополнительная
суточная сводка удалена, чтобы не дублировать основной прогноз.

В описаниях локаций указаны реальные точки расчёта из каталога. Не добавляем
непроверенные сведения о микроклимате и не называем модельный прогноз измерением.

## Отказ API каталогов

Sitemap ждёт каждый источник не более восьми секунд. Для недоступного источника
используется встроенный каталог slugs; успешный источник сохраняется. Резерв
работает и после перезапуска сервера. При исправном API учитывается его актуальный
ответ, включая пустой каталог. Сбой фиксируется в серверном журнале.

При изменении seed-каталога обновите резерв:

~~~powershell
npm run sitemap:catalog:update --workspace @kuda-krym/database
~~~

Соответствие резервного каталога seed-данным проверяется в npm run check.

## Проверки

Unit-тесты проверяют календарь основного прогноза и независимый отказ источников
sitemap. weather-seo.spec.ts проверяет
метаданные, ссылки, основной прогноз без JavaScript и отсутствие переполнения
мобильного экрана. Переходы к прогнозу ожидают серверные данные в пределах
20 секунд, как в существующем тесте перехода к побережью; общий таймаут набора
не увеличивается. Производительность сборки контролирует npm run check:performance;
сценарии планшетов остаются в tablet-performance.spec.ts.

Фактические LCP, INP и CLS после публикации проверяются в Search Console и на
реальных устройствах. Бюджет JS/CSS и браузерные тесты не заменяют полевые метрики.
Изменения не гарантируют индексацию или позиции; причины исключения URL проверяются
в Search Console и Яндекс Вебмастере.

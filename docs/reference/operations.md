# Эксплуатация и источники данных

[К описанию проекта](../../README.md)

Команды выполняются из корня репозитория.

## Запуск в Docker

Production-стек состоит из отдельных контейнеров web, API, PostgreSQL и Redis.
Одноразовый контейнер `migrate` перед запуском API применяет Prisma-миграции.
Начальный каталог пляжей и прибрежных локаций добавляется отдельно и только один
раз, чтобы последующие деплои не перезаписывали данные, изменённые в production.

Создайте локальный файл настроек Compose:

```powershell
Copy-Item compose.env.example .env
```

Замените пароль в `POSTGRES_PASSWORD`, тот же пароль в `DATABASE_URL` и укажите
ключ JavaScript API Яндекс Карт в `NEXT_PUBLIC_YANDEX_MAPS_API_KEY`. Для публичного
развёртывания также укажите фактический адрес сайта в `WEB_ORIGIN` и `SITE_URL`.
Файл `.env` не должен попадать в Git.

Соберите и запустите стек:

```powershell
docker compose up -d --build
docker compose ps
```

При первом запуске новой пустой базы отдельно добавьте начальный каталог:

```powershell
docker compose --profile tools run --rm seed
```

При последующих обновлениях повторять эту команду не нужно.

После успешного запуска сайт доступен по адресу `http://localhost:3000`. PostgreSQL,
Redis и API доступны только внутри сети Compose; наружу публикуется только web.
Состояние и журналы сервисов можно посмотреть командами:

```powershell
docker compose ps
docker compose logs -f api web
```

Остановка не удаляет данные из именованных томов:

```powershell
docker compose down
```


## Переменные окружения

Основные настройки API находятся в `apps/api/.env`:

- `PORT` — порт API;
- `WEB_ORIGIN` — разрешённый origin веб-приложения;
- `DATABASE_URL` — строка подключения PostgreSQL;
- `REDIS_URL` — строка подключения Redis;
- `OSRM_BASE_URL` — адрес сервиса построения маршрутов;
- `PHOTON_BASE_URL` — адрес геопоиска населённых пунктов;
- `RATE_LIMIT_WINDOW_SECONDS` — длительность окна ограничения запросов;
- `RATE_LIMIT_MAX_REQUESTS` — общий лимит запросов на клиента;
- `RATE_LIMIT_EXPENSIVE_MAX_REQUESTS` — общий строгий лимит рекомендаций и маршрутов;
- `TRUST_PROXY_HOPS` — число доверенных reverse proxy перед API.

Веб-приложение использует `API_URL` для обращения к API, `SITE_URL` как публичный
origin сайта и `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` для интерактивных Яндекс Карт.
Получите ключ JavaScript API в кабинете разработчика Яндекса и ограничьте его
разрешёнными доменами. Для Vercel и Docker ключ должен быть доступен во время сборки.
В production задайте `SITE_URL` полным адресом с протоколом, например
`https://example.com`, без пути и завершающего слеша. Для миграций и seed Prisma использует `DIRECT_URL` из
`packages/database/.env`, если он задан; иначе — `DATABASE_URL`.


## Индексация и метаданные

Публичные страницы получают canonical URL, Open Graph, Twitter Cards и
структурированные данные JSON-LD. Главная страница описана как `WebSite`, страницы
пляжей — как `TouristAttraction`, а прибрежных локаций — как `Place`. В разметку
попадают только проверенные данные каталога и координаты.

Файл `/robots.txt` разрешает индексировать публичные страницы, закрывает служебные
API и страницу сравнения. Динамический `/sitemap.xml` содержит главную страницу,
каталоги и все доступные страницы пляжей и прибрежных локаций. После публикации
проверьте, что `SITE_URL` указывает на фактический домен, и отправьте адрес sitemap
в панели поисковых систем.


## Источники и кеширование

Погода и состояние моря загружаются из Open-Meteo и Open-Meteo Marine,
автомобильные маршруты — из OSRM, поиск населённых пунктов — из Photon. Свежий прогноз хранится в Redis 15 минут для
погоды и погодных моделей и 30 минут для моря. Маршруты кешируются на 24 часа.

Прогнозные данные сохраняются до 6 часов. Если внешний источник временно
недоступен, API может вернуть последний сохранённый прогноз с признаком
`STALE`, а интерфейс явно предупредит пользователя, что данные устарели.

Все исходящие HTTP-запросы к Open-Meteo и OSRM ограничены таймаутом 8 секунд.
Ошибки кеша не останавливают API: запрос выполняется напрямую к внешнему
источнику, а при его недоступности используется сохранённый прогноз, если он
ещё находится в пределах шестичасового срока хранения.


## Ограничение запросов

Все публичные API endpoints, кроме health-check, защищены общим лимитом. Расчёт
рекомендаций и маршрутов использует дополнительный общий строгий бюджет, чтобы
дорогие операции нельзя было обойти чередованием двух endpoints. При превышении
API возвращает `429 Too Many Requests`, контрактную ошибку `RATE_LIMIT_EXCEEDED`
и стандартные заголовки `RateLimit` и `Retry-After`.

Счётчики хранятся в Redis и поэтому разделяются между экземплярами API. Если
Redis недоступен при старте, приложение использует локальное хранилище процесса.
Если Redis откажет во время работы, limiter пропускает запросы: сбой кеша не
должен превращаться в недоступность сайта.

Next.js bridge передаёт API проверенный IPv4- или IPv6-адрес посетителя. API не
доверяет proxy-заголовкам по умолчанию. `TRUST_PROXY_HOPS` следует включать только
за контролируемым reverse proxy; значение должно точно соответствовать числу
промежуточных узлов. В Compose между посетителем и API используется один
доверенный hop — контейнер web.


## Достоверность сведений о пляжах

Прибрежные локации отвечают за общий прогноз района, а пляжи представляют
конкретные места со своими координатами. На странице района показываются пляжи
рядом, а со страницы пляжа можно перейти к общему прогнозу побережья. Подробные
правила этой связи описаны в
[`docs/domain/coast-and-beaches.md`](../../docs/domain/coast-and-beaches.md).

Начальный каталог содержит 50 пляжей: 12 на Южном берегу, 11 на восточном
побережье, 11 в Севастопольском регионе, 9 на западном побережье и 7 на
Керченском полуострове. Seed-данные разделены по этим регионам в
`packages/database/prisma/seed-data/beaches`, чтобы каталог можно было
проверять и расширять небольшими независимыми наборами.

Название и координаты пляжа связываются с конкретным объектом OpenStreetMap и
сохраняются вместе с URL источника и датой проверки. Эти ссылки используются
только для идентификации и проверки исходных данных; подложку интерактивной карты
предоставляет Яндекс. OpenStreetMap сам по себе не подтверждает, что пляж
официально открыт, оборудован или безопасен для купания.

Характеристика отображается в публичной карточке только при наличии известного
значения. Поля без подтверждённых сведений хранятся как `UNKNOWN`, но интерфейс
не показывает пользователю строки «данные уточняются». Поэтому отсутствие
сведений о душе, парковке или покрытии не трактуется как отсутствие самого
объекта.

Оперативный статус пляжа, ограничения на купание и качество воды нельзя
выводить из погодного прогноза. Такие сведения могут публиковаться только с
датированным официальным источником. Прогноз погоды и моря помогает оценить
ожидаемые условия, но не заменяет решения спасательных и санитарных служб.


## Фотографии и лицензии

В репозитории хранятся 47 оптимизированных WebP-файла размером 1280 × 800. Все
36 прибрежных локаций имеют собственную обложку. Источником служат файлы
Wikimedia Commons, для которых в seed-данных зафиксированы автор, оригинальная
страница, лицензия, ссылка на её условия и дата проверки.

Для 15 пляжей есть подтверждённая фотография самого пляжа. Остальные карточки
используют обложку связанной прибрежной локации и явно помечают её как «Фото
побережья». Такое изображение показывает район, но не выдаётся за точный снимок
конкретного пляжа.

Перед запуском и сборкой веб-приложения автоматически создаются варианты
фотографий шириной 320, 480, 640, 768, 1024 и 1280 пикселей. Они находятся в
`apps/web/public/images/generated` и не коммитятся в Git.

Скачать отсутствующие файлы из проверенного манифеста и привести их к единому
формату можно командой:

```powershell
npm run images:download --workspace @kuda-krym/database
```

Существующие корректные файлы команда пропускает. Для повторного скачивания
используйте дополнительный аргумент `-- --force`. Добавлять фотографию без
сведений об авторе, источнике и лицензии нельзя.


## Эксплуатация API

API предоставляет отдельные endpoints состояния:

- `GET /api/health` — прежняя общая проверка для обратной совместимости;
- `GET /api/health/live` — процесс запущен и принимает HTTP-запросы;
- `GET /api/health/ready` — API готов к работе и PostgreSQL отвечает. При
  недоступной базе endpoint возвращает статус `503`.

Каждому HTTP-запросу назначается идентификатор, который возвращается в заголовке
`x-request-id`. Журналы API выводятся в JSON и содержат request ID, метод, путь,
HTTP-статус и длительность запроса. Внутренние причины серверных ошибок
записываются в журнал, но не раскрываются клиенту.

При получении `SIGINT` или `SIGTERM` API прекращает принимать новые соединения,
дожидается закрытия HTTP-сервера, затем отключается от Redis и PostgreSQL.


## Доступность интерфейса

Интерфейс поддерживает навигацию с клавиатуры: при первом нажатии `Tab` появляется
ссылка перехода к основному содержимому, интерактивные элементы имеют заметный
фокус, а текущий раздел отмечается в основной навигации. Формы используют связанные
подписи и группы полей, а динамические результаты и ошибки доступны вспомогательным
технологиям.

При системной настройке `prefers-reduced-motion: reduce` CSS-анимации и плавные
перемещения карты отключаются. Публичные страницы автоматически проверяются по
правилам WCAG A/AA с помощью `@axe-core/playwright`; отдельный E2E-сценарий проверяет
фактический переход по клавиатуре.


## Подготовка к публикации

Перед первым публичным запуском проверьте production-переменные. Для новой пустой
базы одной командой примените миграции и добавьте начальный каталог:

```powershell
npm run check:release-config
npm run database:bootstrap
```

При обычных обновлениях выполняйте `npm run database:migrate`; повторно запускать
`database:bootstrap` не нужно. После публикации доступность web, API, PostgreSQL,
`robots.txt` и `sitemap.xml` проверяется командой `npm run check:deployment`.

Полный порядок первого запуска, обновления и безопасного отката описан в
[`docs/deployment/release-checklist.md`](../../docs/deployment/release-checklist.md).

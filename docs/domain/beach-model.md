# Модель пляжа

Статус документа: проект первой версии.

## Назначение

Модель хранит сведения, необходимые для подбора пляжа, объяснения рекомендации
и отображения карточки. Она не описывает прогноз погоды, состояние моря или
маршрут: эти данные меняются во времени и относятся к отдельным сущностям.

Основной принцип: неизвестное значение не заменяется догадкой. Для важных
характеристик сохраняются источник и результат проверки.

## Состав модели

Данные разделены на пять сущностей:

1. `Beach` — идентичность, положение и редакционный статус пляжа.
2. `BeachProfile` — характеристики, используемые при подборе.
3. `DataSource` — источник информации.
4. `BeachFieldEvidence` — подтверждение конкретной характеристики источником.
5. `BeachImage` — изображение и обязательная информация о правах.

Такое разделение не смешивает стабильные сведения, проверяемые признаки и
лицензионные данные фотографий в одной таблице.

## Beach

| Поле | Тип | Обязательное | Назначение |
| --- | --- | --- | --- |
| `id` | UUID | да | Внутренний идентификатор |
| `slug` | string | да | Уникальный адрес страницы |
| `name` | string | да | Публичное название |
| `officialName` | string | нет | Название из официального реестра |
| `region` | enum | да | Территория для каталога |
| `locality` | string | нет | Ближайший населённый пункт |
| `latitude` | decimal | да | Широта центра пляжа |
| `longitude` | decimal | да | Долгота центра пляжа |
| `osmType` | enum | нет | Тип объекта OpenStreetMap |
| `osmId` | bigint/string | нет | Идентификатор OpenStreetMap |
| `officialRegistryId` | string | нет | Идентификатор официального набора |
| `description` | text | нет | Собственное редакционное описание |
| `publicationStatus` | enum | да | Состояние публикации |
| `createdAt` | datetime | да | Дата создания записи |
| `updatedAt` | datetime | да | Дата последнего изменения |

Ограничения:

- `slug` уникален и после публикации меняется только с настройкой редиректа;
- широта находится в диапазоне от `-90` до `90`, долгота — от `-180` до `180`;
- пара `osmType + osmId` уникальна, если OSM-объект указан;
- отсутствие `officialRegistryId` допустимо для пляжа вне официального реестра;
- опубликовать пляж без координат, названия и профиля нельзя.

### Region

Первая версия использует крупные территории каталога, а не административные
районы:

- `WEST_CRIMEA` — западное побережье;
- `SOUTH_COAST` — Южный берег Крыма;
- `EAST_CRIMEA` — восточное побережье;
- `SEVASTOPOL` — Севастополь;
- `KERCH_PENINSULA` — Керченский полуостров.

Границы территорий должны быть зафиксированы при подготовке начального набора
пляжей. Если одного значения окажется недостаточно, позже добавляется отдельный
справочник территорий без изменения остальных сущностей.

### PublicationStatus

- `DRAFT` — карточка заполняется и недоступна публично;
- `PUBLISHED` — участвует в каталоге и рекомендациях;
- `DISABLED` — временно исключена без удаления истории.

Физическое удаление опубликованных пляжей не используется.

## BeachProfile

У каждого пляжа ровно один профиль. Все справочные значения имеют вариант
`UNKNOWN`: это полноценное состояние «нет проверенной информации», а не ошибка.

| Поле | Значения | Использование |
| --- | --- | --- |
| `surface` | `UNKNOWN`, `SAND`, `PEBBLE`, `MIXED`, `ROCK` | Фильтр по покрытию |
| `waterEntry` | `UNKNOWN`, `GENTLE`, `MODERATE`, `STEEP` | Поездка с детьми |
| `childSuitability` | `UNKNOWN`, `SUITABLE`, `LIMITED`, `UNSUITABLE` | Подбор для семьи |
| `infrastructure` | `UNKNOWN`, `NONE`, `BASIC`, `DEVELOPED` | Комфорт на пляже |
| `parking` | `UNKNOWN`, `NONE`, `REMOTE`, `NEARBY`, `ON_SITE` | Карточка и маршрут |
| `accessibility` | `UNKNOWN`, `LIMITED`, `ACCESSIBLE` | Доступность |
| `bayProtection` | `UNKNOWN`, `OPEN`, `PARTIAL`, `PROTECTED` | Поправка на волны |
| `coastlineBearing` | `0..359` или `null` | Направление берега |
| `windExposure` | `UNKNOWN`, `LOW`, `MEDIUM`, `HIGH` | Поправка на ветер |
| `waveExposure` | `UNKNOWN`, `LOW`, `MEDIUM`, `HIGH` | Поправка на волны |
| `hasToilet` | `UNKNOWN`, `YES`, `NO` | Инфраструктура |
| `hasShower` | `UNKNOWN`, `YES`, `NO` | Инфраструктура |
| `hasChangingRoom` | `UNKNOWN`, `YES`, `NO` | Инфраструктура |

`coastlineBearing` означает направление наружной нормали от берега к морю в
градусах: `0` — север, `90` — восток, `180` — юг, `270` — запад. Это определение
используется одинаково при импорте геометрии и в scoring-модуле.

Поля `childSuitability`, `windExposure` и `waveExposure` являются редакционными
оценками, а не результатом текущего прогноза. Алгоритм обязан рассматривать их
как коэффициенты и показывать пользователю причину влияния на результат.

## DataSource

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | UUID | Идентификатор источника |
| `type` | enum | Категория источника |
| `title` | string | Понятное название |
| `url` | string | Ссылка на документ, набор или страницу |
| `license` | string/null | Лицензия, если применима |
| `retrievedAt` | datetime | Когда источник был получен |

Типы источников:

- `OFFICIAL_REGISTRY`;
- `OPENSTREETMAP`;
- `WIKIMEDIA_COMMONS`;
- `OWNER_PROVIDED`;
- `FIELD_CHECK`;
- `EDITORIAL_RESEARCH`.

Закрытые карты, туристические сайты и фотографии без понятных условий
использования не копируются в базу как источники данных или изображений.

## BeachFieldEvidence

Сущность связывает конкретное поле пляжа или профиля с источником.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | UUID | Идентификатор подтверждения |
| `beachId` | UUID | Проверяемый пляж |
| `field` | enum | Какое поле подтверждается |
| `sourceId` | UUID | Источник сведений |
| `status` | enum | Результат проверки |
| `verifiedAt` | datetime/null | Когда выполнена ручная проверка |
| `note` | string/null | Краткое пояснение редактора |
| `isPrimary` | boolean | Основное подтверждение поля |

Статусы проверки:

- `IMPORTED` — получено автоматически и ещё не проверено;
- `MANUALLY_CHECKED` — подтверждено редактором;
- `CONFLICTING` — источники противоречат друг другу;
- `STALE` — сведения требуют повторной проверки;
- `REJECTED` — источник признан неподходящим для этого поля.

Для одного поля допускается несколько подтверждений, но только одно может быть
основным. Изменение значения профиля не удаляет старые подтверждения. При
расхождении источников поле получает статус `CONFLICTING`, а публичный интерфейс
не должен выдавать такое значение за достоверное.

В первой версии подтверждения обязательны для следующих полей:

- `surface`;
- `waterEntry`;
- `childSuitability`;
- `parking`;
- `accessibility`;
- `bayProtection`;
- `coastlineBearing`;
- `windExposure`;
- `waveExposure`.

## BeachImage

| Поле | Тип | Обязательное | Назначение |
| --- | --- | --- | --- |
| `id` | UUID | да | Идентификатор изображения |
| `beachId` | UUID | да | Пляж |
| `url` | string | да | Адрес используемого файла |
| `sourceUrl` | string | да | Страница оригинала |
| `title` | string | нет | Название работы |
| `author` | string | да | Автор или правообладатель |
| `license` | string | да | Обозначение лицензии |
| `licenseUrl` | string | нет | Ссылка на условия лицензии |
| `alt` | string | да | Альтернативный текст |
| `sortOrder` | integer | да | Порядок в галерее |
| `isCover` | boolean | да | Обложка карточки |
| `createdAt` | datetime | да | Дата добавления |

У пляжа не более одной обложки. Изображение без автора, источника или лицензии
не публикуется. Удаление изображения не должно удалять пляж.

## Готовность карточки к публикации

Карточка может перейти в `PUBLISHED`, когда:

- заполнены название, slug, территория и координаты;
- создан `BeachProfile`;
- ключевые поля для scoring имеют проверенное значение либо явно равны
  `UNKNOWN`;
- у каждого известного ключевого значения есть основное подтверждение;
- описание написано редакцией и не скопировано из внешнего источника;
- каждая опубликованная фотография имеет сведения о правах.

Наличие фотографии не является обязательным для первой публикации.

## Что не входит в эту модель

- почасовой прогноз погоды и моря;
- рассчитанные баллы и уверенность прогноза;
- маршруты и время в пути;
- отзывы, оценки и фотографии пользователей;
- текущая загруженность пляжа;
- отели, рестораны и достопримечательности;
- произвольные адреса и геолокация пользователя.

Эти данные либо относятся к другим модулям, либо сознательно исключены из
первой версии.

## Решения для Prisma-схемы

При реализации в PostgreSQL необходимо:

- хранить координаты как точные десятичные значения, не как `float`;
- создать уникальные индексы для `slug` и пары `osmType + osmId`;
- связать `BeachProfile` с `Beach` отношением один-к-одному;
- запретить каскадное удаление источников, на которые есть подтверждения;
- удалять профиль, подтверждения и изображения только вместе с черновиком
  пляжа; опубликованные записи деактивировать;
- создать индексы по `publicationStatus`, `region`, `surface` и
  `childSuitability`;
- реализовать правило одной обложки и одного основного подтверждения поля
  частичными уникальными индексами PostgreSQL либо транзакционной проверкой.

До создания миграции нужно подготовить 10 реальных тестовых пляжей и убедиться,
что справочники описывают их без свободных строк и искусственных исключений.

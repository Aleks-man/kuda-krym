# Развёртывание на VPS

Production-стек запускает Caddy, Next.js, API, PostgreSQL и Redis отдельными
контейнерами в одном Compose-проекте. В интернет публикуются только порты 80 и
443. API, PostgreSQL и Redis доступны только внутри сети Compose.

Образы приложения собираются в GitHub Actions после успешного прохождения всех
проверок ветки `main` и публикуются в GitHub Container Registry. VPS скачивает
готовые образы и не тратит ресурсы на сборку Next.js.

## Файлы

- `compose.yaml` — production-сервисы, лимиты памяти и ротация логов;
- `Caddyfile` — HTTPS, защитные заголовки и проксирование Next.js;
- `.env.example` — шаблон переменных без production-секретов.

## Первый запуск

На сервере создайте закрытый каталог приложения и скопируйте в него файлы из
`infra/vps`. Файл `.env` создаётся из `.env.example`, имеет права `600` и не
попадает в Git.

После публикации образов сначала запускается миграция, затем сервисы приложения.
Seed выполняется отдельно и только один раз для новой пустой базы:

```bash
docker compose --profile tools run --rm seed
```

Повторять seed при обычных обновлениях нельзя: production-данные могут быть
перезаписаны.

## Данные и откат

PostgreSQL, Redis и сертификаты Caddy хранятся в именованных Docker-томах.
Команда `docker compose down` не удаляет их. Использовать флаг `--volumes` в
production нельзя без отдельного подтверждения и проверенной резервной копии.

Для отката задайте `IMAGE_TAG` равным SHA предыдущего успешного коммита и снова
запустите Compose. Миграции Prisma откатываются только отдельной совместимой
миграцией; `prisma migrate reset` в production запрещён.
